# Spike: Managed Bots (کار ۱)

> تاریخ: 2026-10-03 · aiogram 3.31 (Bot API 10.3) · اسکریپت: `backend/src/obot/spike/managed_bots.py`
> ربات کارخانه‌ی تستی: `@obotfactorybot` · ربات ساخته‌شده: `@obot_spike_fdd351_bot`

## نتایج

| سوال | نتیجه |
|---|---|
| ساخت ربات با `KeyboardButtonRequestManagedBot` | ✅ کار می‌کند. آپدیت `managed_bot` و پیام سرویسی `managed_bot_created` تقریباً هم‌زمان می‌رسند. |
| دریافت توکن با `getManagedBotToken` | ✅ بلافاصله پس از ساخت، و **پس از ری‌استارت هم** (تکرارپذیر). |
| آیا ساخت = Start؟ ربات جدید می‌تواند قبل از `/start` به سازنده پیام دهد؟ | ❌ خیر: `Bad Request: chat not found`. پس از `/start` کاربر، ارسال کار می‌کند. |
| تنظیمات دسترسی پیش‌فرض | `is_access_restricted=False` — ربات برای همه قابل دسترس است. |
| Kill Switch با `replaceManagedBotToken` | ✅ توکن قبلی **فوراً** `Unauthorized` می‌شود. |
| پشتیبانی aiogram | ✅ همه‌ی انواع و متدها موجودند؛ نیازی به فراخوانی خام نیست. |

## پیامدها برای طراحی

1. **مرحله‌ی «باز کردن ربات» و وضعیت `waiting_start` الزامی است** (SPEC §۳.۲ مرحله‌ی ۶ و §۷.۲ تأیید شد).
2. **`replaceManagedBotToken` هم یک آپدیت `managed_bot` تولید می‌کند.** هندلر `managed_bot` باید:
   - idempotent باشد (ساخت ربات تکراری در DB ایجاد نکند)،
   - وضعیت `disabled` را رعایت کند — در اسپایک، هندلر بعد از `/kill` ربات را با توکن جدید دوباره روشن کرد.
   - این آپدیت همچنین برای تغییر مالک ربات ارسال می‌شود؛ فیلد `user` را با `owner_id` مقایسه و تغییر مالک را ثبت کنیم.
3. **توکن همیشه از کارخانه قابل بازیابی است.** ذخیره‌ی رمزنگاری‌شده‌ی توکن (طبق SPEC) حفظ می‌شود تا برای هر پیام API call اضافه نداشته باشیم، اما در صورت از دست رفتن کلید رمزنگاری، توکن‌ها قابل بازیابی‌اند.

## یافته‌ی بعدی: کلاینت iOS

- روی **Telegram iOS** دکمه‌ی `KeyboardButtonRequestManagedBot` صفحه‌ی خالی (یا صفحه‌ی «Forward» با اردک) باز می‌کند و رباتی ساخته نمی‌شود. روی Desktop کار می‌کند.
- **راه جایگزین:** لینک `https://t.me/newbot/{factory_username}/{suggested_username}?name=...` روی iOS کار می‌کند و همان آپدیت `managed_bot` و پیام سرویسی `managed_bot_created` را تولید می‌کند.
- ربات کارخانه هر دو را نشان می‌دهد: دکمه‌ی کیبورد + دکمه‌ی لینک.

## سوال‌های باز باقی‌مانده

- آیا Webhook تنظیم‌شده پس از `replaceManagedBotToken` (چرخش توکن، نه Kill) باقی می‌ماند؟ ← در کار ۱ با Webhook واقعی بررسی شود.
- سقف تعداد ربات‌های مدیریت‌شده به ازای کاربر/مدیر هنوز مشخص نیست ← در پایش production.
