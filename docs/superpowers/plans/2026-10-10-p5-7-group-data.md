# P5-7: Group Data (Family Shopping List) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A bot's template can hold `group` collections. Mentioned in a Telegram group, the bot reads and writes that group's own records: members who started the bot add items and change their own, group admins change and delete anyone's. A family can keep one shared shopping list just by talking to the bot in their group.

**Architecture:**
- `obot.data` already models group scope (`DataSpace.tg_chat_id`, `is_group_admin`, row filters, unique keys per chat). This plan wires it to Telegram.
- `DataService` gets an optional `GroupChat` (chat id, a lazy `is_admin` check, title). With it, every call builds the group's `DataSpace`. The admin check runs only for edits and deletes.
- A new `obot.telegram.group_access` module asks Telegram (`getChatMember`) whether someone is in a group and whether they are an admin. Chat replies cache the admin answer in Redis for 5 minutes. The delete button always asks Telegram fresh.
- The delete confirmation card goes to the person's private chat. Its callback data carries the group's chat id.
- Scheduled tasks posting into a group see that group's collections. `ask_bot` and other bots' chain steps still get no data from a group.
- The factory designer may draft `group` collections. Record notifications for group records name the group.

**Tech Stack:** Python 3.13, aiogram 3, SQLAlchemy 2 async, pydantic 2, Redis, pytest-asyncio.

## Decisions taken for this plan (from the 2026-10-10 direction)

- **Chat boundary:** in a group, the data tools see only group collections, and records are scoped to that chat. In private chats, group collections stay hidden. The private catalog only *names* them, so the bot can say "ask me in the group".
- **Admin check:** `getChatMember`, cached in Redis for 300 s per (bot, chat, person). It runs only when an edit or delete needs it, and only when the bot has group collections. A Telegram error counts as "not admin" and is not cached.
- **Delete card:** it goes to the person's private chat. The callback is `data:del:{collection}:{record}:{chat}`. The handler re-checks membership and admin status with a fresh `getChatMember`, never the cache. Someone who left the group can no longer delete.
- **Tasks:** a task posting to a group (or supergroup) runs its own bot with that group's data space. Its user was just verified as an admin of that chat (`_cannot_run`), so the space is admin. Channels get no data. Other bots' chain steps and `ask_bot` from a group get no data.
- **Factory:** the designer may draft `group` collections. `notify_owner` on a group collection is refused (existing `check_events`). Notifications and reminders go privately to the record's author.
- **Panel:** group data is out of scope. The API process has no bot clients to verify group membership, so group collections stay hidden in the panel as today (`visible()` already hides them when `tg_chat_id` is None).
- **Supergroup migration:** when a group's chat id changes, its data is not moved. This is out of scope and recorded in the spec.

## Global Constraints

- **Records only through obot.data:** records are read and written only through `obot.data` with a `DataSpace`. Never query `Record` or `RecordKey` elsewhere. The one new record lookup (`event_chat`) lives in `obot/data/events.py`.
- **Chat boundary:**
  - A request from a group builds `DataSpace(tg_chat_id=<group>)`.
  - Personal and shared collections are never visible there (`space.visible`).
  - A private request never sets `tg_chat_id`.
- **Outgoing messages:** all outgoing Telegram messages go through `runtime.sender.send_text`.
- **Plan limits:** they come from config. Group records count against the bot owner's plan (existing `payer`).
- **Commits:**
  - **Message:** one plain English imperative sentence, then a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - **Never commit** the user's untracked `backend/avatars.jsonl` or `backend/scripts/`. Use `git add` with explicit paths only.
  - **Ruff fixes:** never run `ruff --fix` outside `src/` and `tests/`.
- **Checks** (run from `backend/`): `uv run pytest -q && uv run ruff check . && uv run ruff format --check .`
- **i18n:** every new key gets both `en` and `fa` entries in `src/obot/i18n.py`.

```python
# backend/src/obot/telegram/group_access.py
"""Who is in a group and who manages it, as Telegram says (SPEC 8.8 group data)."""

from dataclasses import dataclass

from aiogram import Bot as Client
from aiogram.enums import ChatMemberStatus
from aiogram.exceptions import TelegramAPIError

ADMIN_STATUSES = (ChatMemberStatus.ADMINISTRATOR, ChatMemberStatus.CREATOR)
ADMIN_CACHE_SECONDS = 300


@dataclass(frozen=True)
class GroupRole:
    is_admin: bool


async def group_role(client: Client, chat_id: int, tg_user_id: int) -> GroupRole | None:
    """The person's role in the group now; None if they are not in it. Telegram errors
    (TelegramAPIError) are left to the caller."""
    member = await client.get_chat_member(chat_id, tg_user_id)
    if member.status in ADMIN_STATUSES:
        return GroupRole(is_admin=True)
    if member.status == ChatMemberStatus.MEMBER:
        return GroupRole(is_admin=False)
    if member.status == ChatMemberStatus.RESTRICTED and getattr(member, "is_member", False):
        return GroupRole(is_admin=False)
    return None


class CachedGroupAdmin:
    """Whether a person is an admin of a group, asked of Telegram at most every few minutes
    per bot, group and person. A Telegram error counts as no and is not remembered."""

    def __init__(self, redis, client: Client, bot_id: int, chat_id: int, tg_user_id: int) -> None:
        self._redis, self._client = redis, client
        self._chat_id, self._tg_user_id = chat_id, tg_user_id
        self._key = f"group-admin:{bot_id}:{chat_id}:{tg_user_id}"

    async def __call__(self) -> bool:
        cached = await self._redis.get(self._key)
        if cached is not None:
            return cached in (b"1", "1")
        try:
            role = await group_role(self._client, self._chat_id, self._tg_user_id)
        except TelegramAPIError:
            return False
        admin = role is not None and role.is_admin
        await self._redis.set(self._key, "1" if admin else "0", ex=ADMIN_CACHE_SECONDS)
        return admin
```
